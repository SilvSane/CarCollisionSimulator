# Car Collision Simulator

Симулятор встречного движения двух прямоугольников («машин») по координатной оси. Пользователь задаёт уравнения движения `x(t)` для каждой машины, выбирает цвета и точность расчёта — программа проверяет, что машины действительно едут навстречу и столкнутся, считает траектории, а потом красиво проигрывает всё это на экране: анимация, график, ползунок времени, статистика.

**Пример задачи:** две машины едут навстречу друг другу. Слева — по закону `x = 2*t + 0.2*t*t`, справа — по закону `x = 10 - 3*t`. Программа должна найти момент их встречи, показать анимацию и графики, дать перемотать процесс туда-сюда.

Автор проекта — **Николай**.

## Что должна уметь программа

### Ввод уравнений

- Два поля: для левой машины и для правой.
- В каждом поле пользователь пишет закон движения, например `2*t + 0.2*t*t`.
- Программа понимает разные формы записи: `t`, `t^2`, `t**2`, `t*t`, `2t`, `0.5*t`, `:`, `/`, скобки, десятичные дроби, пробелы.
- **На каждый введённый символ** программа проверяет поле. Если символ недопустимый или запись сломана — поле подсвечивается красным.
- Кнопка **«Проверить уравнения»** активна, только если в оба поля введено **больше 3 символов** (после удаления пробелов по краям). Проверка идёт на каждый символ.

### Цвета и направления

- Рядом с каждым полем — выпадающий список с цветными кружками. Пользователь выбирает цвет своей машины.
- Рядом с каждым цветом — квадратик, в котором показывается направление:
  - **→** — машина едет вправо,
  - **←** — машина едет влево,
  - **✕** — направление не определено (или что-то пошло не так).

### Точность расчёта

Выпадающий список `dt` (шаг времени):

| Название | Примерный шаг |
|---|---|
| Ориентировочная | ~1 секунда |
| Стандартная | ~50 миллисекунд |
| Повышенная | ~5 миллисекунд |

### Проверка уравнений

Когда пользователь жмёт «Проверить уравнения», программа:

1. Отправляет введённые уравнения в **Парсер** (внутренняя часть программы, которая умеет читать формулы).
2. Парсер превращает текст в математическое выражение.
3. Программа быстро смотрит (несколько первых шагов), куда едет машина: вправо или влево.
4. В квадратики направлений ставится соответствующая стрелка.
5. Проверяется, что машины **едут навстречу** и что **столкновение вообще произойдёт**.
6. Если всё в порядке:
   - фон квадратиков со стрелками загорается зелёным,
   - разблокируется кнопка **«Старт»**.
7. Если что-то не так:
   - высвечивается **сообщение прямо на странице** с причиной (например, «Обе машины едут вправо — столкновения не будет»).
   - **Никаких `alert()` — в программе их быть не должно.**

### Запуск расчёта

Когда пользователь жмёт «Старт», программа отправляет на сервер:

- разобранные уравнения,
- выбранную точность `dt`,
- начальные позиции машин.

Сервер считает координаты `x(t)` для обеих машин на каждом шаге `t + dt` — **до момента столкновения включительно**. Момент столкновения определяется заранее, чтобы из-за погрешности расчёты не уходили дальше, чем нужно.

Ответ приходит в формате **JSON** — это просто текстовый формат для передачи данных. В нём лежат координаты `x` и время `t` для каждой машины на каждом шаге.

### Отрисовка

По полученному JSON программа:

- рисует координатные оси и две машины в виде прямоугольников выбранных цветов,
- машины едут навстречу друг другу,
- траектории можно включать и выключать,
- на графике красиво отмечается момент столкновения.

### Управление временем

- **Ползунок времени** в процентах — можно откатывать процесс назад и вперёд.
- **Таймер** рядом с ползунком показывает реальное время: секунды, минуты, миллисекунды.
- В таймер **можно вводить время вручную** — это работает так же, как передвинуть ползунок.
- Поле таймера валидируется так же строго, как поля уравнений.

### Статистика

Отдельная панель с результатами эксперимента:

- сколько длился эксперимент,
- когда произошло столкновение,
- средняя скорость каждой машины,
- пройденное расстояние каждой машиной.

### Общие требования к интерфейсу

- **Никаких `alert()`.** Совсем. Нигде.
- У каждого поля, ползунка и кнопки — подпись (лейбл), что это такое.
- У элементов — всплывающие подсказки.
- Если расчёт уже запускался хотя бы один раз, надпись на кнопке **«Старт»** меняется на **«Учесть изменения»**.

## Как устроен проект

Проект разделён на **три независимые части**:

```
┌──────────────────────────────────────────────────────┐
│                   Браузер                            │
│  ┌────────────────────────────────────────────────┐  │
│  │  UI  — то, что видит пользователь              │  │
│  │  • поля ввода, кнопки, ползунки                │  │
│  │  • валидация                                   │  │
│  │  • анимация (P5.js)                            │  │
│  │  • графики (Plotly.js)                         │  │
│  └────────────────┬───────────────────────────────┘  │
└───────────────────┼──────────────────────────────────┘
                    │  запрос → JSON
                    ▼
┌──────────────────────────────────────────────────────┐
│  Controller — «приёмная»                             │
│  • принимает запросы из UI                           │
│  • передаёт их в Core                                │
│  • возвращает ответ обратно в UI                     │
└───────────────────┬──────────────────────────────────┘
                    │  вызов C# методов
                    ▼
┌──────────────────────────────────────────────────────┐
│  Core — «мозг»                                       │
│  • читает уравнения (Парсер)                         │
│  • проверяет их                                      │
│  • считает траектории                                │
│  • находит момент столкновения                       │
│  • считает статистику                                │
└──────────────────────────────────────────────────────┘
```

**Почему так:**

- `Core` — чистый C#, ничего не знает про кнопки и про интернет. Просто считает.
- `UI` — чистые HTML/CSS/JS, ничего не знает про C#. Просто рисует то, что ей прислали.
- `Controller` — тонкий «переводчик» между ними. Принимает запрос из UI, дёргает Core, отдаёт ответ обратно в UI.

Благодаря этому Карина может спокойно писать Core и Controller, а Александр — спокойно верстать UI, даже пока Core ещё не готов. Они встречаются только на формате JSON.

## Формат данных между частями программы

Это **самое главное** место. Как только формат зафиксирован — Карина и Александр могут работать полностью независимо.

### 1. Проверка уравнений

UI отправляет:

```json
{
  "equations": {
    "left":  "2*t + 0.2*t*t",
    "right": "10 - 3*t"
  },
  "initialPositions": {
    "left":  0.0,
    "right": 10.0
  },
  "carWidth": 1.0
}
```

Сервер отвечает:

```json
{
  "isValid": true,
  "directions": {
    "left":  "right",
    "right": "left"
  },
  "willCollide": true,
  "predictedCollisionTime": 1.6863,
  "errors": []
}
```

Если что-то не так:

```json
{
  "isValid": false,
  "directions": {
    "left":  "right",
    "right": "right"
  },
  "willCollide": false,
  "predictedCollisionTime": null,
  "errors": [
    {
      "code": "SAME_DIRECTION",
      "field": "right",
      "message": "Обе машины движутся вправо — столкновения не произойдёт."
    }
  ]
}
```

Возможные `code` в ошибках:

| `code` | Что значит |
|---|---|
| `PARSE_ERROR` | Не удалось разобрать уравнение. |
| `UNKNOWN_VARIABLE` | В уравнении есть переменная, отличная от `t`. |
| `SAME_DIRECTION` | Машины движутся в одну сторону. |
| `NO_COLLISION` | При таких начальных позициях столкновения нет. |
| `COLLISION_BEHIND` | Момент столкновения в прошлом (`t < 0`). |

Значения `directions`: `"left"`, `"right"`, `"unknown"`.

### 2. Полный расчёт

UI отправляет:

```json
{
  "equations": {
    "left":  "2*t + 0.2*t*t",
    "right": "10 - 3*t"
  },
  "initialPositions": {
    "left":  0.0,
    "right": 10.0
  },
  "carWidth": 1.0,
  "dt": 0.05
}
```

Сервер отвечает:

```json
{
  "meta": {
    "dt": 0.05,
    "collisionTime": 1.6863,
    "carWidth": 1.0,
    "initialPositions": { "left": 0.0, "right": 10.0 }
  },
  "samples": [
    { "t": 0.00,   "left": 0.0000, "right": 10.0000 },
    { "t": 0.05,   "left": 0.1005, "right":  9.8500 },
    { "t": 0.10,   "left": 0.2020, "right":  9.7000 },
    { "t": 1.6863, "left": 3.9413, "right":  4.9411 }
  ],
  "statistics": {
    "duration": 1.6863,
    "collisionTime": 1.6863,
    "left": {
      "averageSpeed": 2.338,
      "distance": 3.941,
      "direction": "right"
    },
    "right": {
      "averageSpeed": -3.000,
      "distance": 5.059,
      "direction": "left"
    }
  }
}
```

**Правила для массива `samples`:**

- Идёт строго по возрастанию `t`.
- Шаг между соседними `t` — ровно `dt` (последний шаг может быть урезан до момента столкновения).
- Последний элемент — момент столкновения (`t == meta.collisionTime`).
- `left` и `right` — координаты левой и правой машины.

## Адреса, по которым общаются части программы

| Метод | Адрес | Что делает | Что принимает | Что возвращает |
|---|---|---|---|---|
| POST | `/api/simulate/check` | Проверить уравнения и предсказать столкновение | JSON из раздела «Проверка уравнений» | JSON оттуда же |
| POST | `/api/simulate/run` | Полный расчёт траекторий | JSON из раздела «Полный расчёт» | JSON оттуда же |

**Пояснение:**

- **POST** — способ отправки данных, при котором параметры кладутся в «тело» запроса.
- **`/api/simulate/check`** и **`/api/simulate/run`** — просто адреса, как страницы в интернете, только для программ.

Оба адреса работают синхронно: UI отправил → подождал → получил ответ. Никаких очередей и опросов «готово или нет».

## Как работают Карина и Александр

### Карина (папки `Core/` и `Controller/`)

1. Открывает решение `CarCollisionSimulator.sln` в Visual Studio.
2. Пишет код в `Core/Physics/` и `Controller/`.
3. Проверяет, что решение собирается.
4. Открывает PR в `development`.

Подробное ТЗ — в файле `docs/TZ-Karina.md`.

### Александр (папка `UI/`)

1. Открывает папку `UI/` в VS Code.
2. Ставит расширение **Live Server**.
3. Запускает `index.html` через **«Open with Live Server»** (не двойным кликом — иначе браузер запретит читать локальные JSON).
4. Работает с данными из `UI/data/check.json` и `UI/data/run.json` — как будто это ответ от сервера Карины.
5. Когда Карина запустит сервер — **один раз** меняет содержимое `UI/js/api.js`, чтобы ходить на реальный адрес.
6. Открывает PR в `development`.

Подробное ТЗ — в файле `docs/TZ-Aleksandr.md`.

### Николай

- Смотрит все пул-реквесты в `development` и одобряет (или отправляет на доработку).
- Периодически вливает `development` в `main`.
- Разруливает споры, если Карина и Александр не сходятся по формату JSON.

## Правила совместной работы

### Ветки

| Ветка | Что это |
|---|---|
| `main` | Финальная, стабильная версия. Пушит **только Николай**. |
| `development` | Ветка разработки. Сюда стекаются готовые задачи через PR. PR одобряет **Николай**. |
| `feature/...` | Личные ветки Карины и Александра. Здесь они пишут код. |

### Как создать свою ветку

```bash
git checkout development
git pull
git checkout -b feature/ui
```

(Александр — `feature/ui`, Карина — `feature/core`.)

### Коммиты

**Важно: все сообщения коммитов пишем на английском языке.** Это стандарт в мире программирования — так понятнее, и если проект попадёт на GitHub в открытый доступ, любой иностранный разработчик поймёт историю изменений.

Формат: `тип(область): краткое описание`

Типы:

| Тип | Когда использовать |
|---|---|
| `feat` | Добавляешь новую функциональность |
| `fix` | Исправляешь баг |
| `docs` | Изменения только в документации |
| `chore` | Служебное: настройка проекта, зависимости, конфиги |
| `refactor` | Переписал код, не меняя поведение |
| `style` | Правки форматирования, пробелов, точек с запятой |

Область (`scope`) — что именно затронуто. У нас основных три: `core`, `controller`, `ui`.

Примеры:

- `feat(core): add equation parser`
- `feat(core): implement collision detection`
- `fix(core): handle division by zero`
- `feat(controller): add /api/simulate/check endpoint`
- `fix(ui): correct timer validation`
- `feat(ui): add time slider`
- `docs: update README`
- `chore: initial project setup`

Если изменение не привязано ни к одной области — просто пиши без скобок:

- `docs: update README`
- `chore: bump .NET version`

### Пул-реквесты

- Один PR — одна задача.
- PR создаётся из `feature/...` в `development`.
- Одобряет Николай. Он же делает merge.
- В `main` изменения попадают только через Николая.

### Если нужно поменять формат JSON

**Это обсуждается втроём.** Меняем — и одновременно правим обе стороны, иначе один сломает другого.
